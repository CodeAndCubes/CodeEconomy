# CodeEconomy

Серверная экономика для Minecraft 1.7.10. Валюты в toml, счёта игроков и журнал операций в
состоянии мира, деньги только в целых минорных единицах, перевод атомарный: списание и зачисление
это одна строка журнала.

Каждая мутация несёт `transactionId`, повтор возвращает записанный исход с кодом `DUPLICATE` и
второй раз деньги не двигает. Журнал append-only, чекпоинт ускоряет загрузку, `/eco verify`
сверяет after-балансы каждой записи.

Клиентской части нет: ванильный клиент заходит на сервер с CodeEconomy без этого мода.

## Требования

- Minecraft 1.7.10, запуск на Java 8.
- CodeCore 0.1.0 или новее, зависимость `required-after:codecore`.

## Сборка

Нужен JDK 17 или 21, wrapper скачает Gradle сам.

```
./gradlew build
```

В `build/libs` появятся универсальный `CodeEconomy-0.1.0.jar` для dev-запусков и
`CodeEconomy-0.1.0-server.jar` для сервера. Раздавать универсальный jar игрокам нельзя: в нём
есть серверный код.

## Подключение

1. Собрать и опубликовать зависимости локально: `CodeSides` и `CodeCore` через `publishToMavenLocal`.
2. Здесь: `./gradlew build`.
3. На сервер в `mods` положить `codecore` и `CodeEconomy-0.1.0-server.jar`.

Мод грузится после CodeCore, порядок задаёт `required-after:codecore`. Файлы настроек лежат в
`config/code/economy/`: `economy.toml` с настройками мода и `economy-currencies.toml` с валютами.
Общее для всей линейки живёт в главном файле `config/code/config.toml`: провайдер хранилища и
автосейв в `[storage]`, записи в лог в `[audit]`, валюта по умолчанию и границы перевода в
`[economy]`. Ключ, который есть в главном файле, в `economy.toml` не повторяется.

Балансы в `world/code/economy/`: `economy-accounts.json` с чекпоинтом и `economy-journal.jsonl` с
журналом, оба json, оба переезжают вместе с сохранением мира.

Автосейв экономики общий с линейкой, 30 секунд. Прежний интервал возвращается строкой в главном
файле:

```toml
[storage.economy]
autosaveSeconds = 120
```

Права мода перечислены в [perms.md](perms.md).

## Роль economy и её владелец

В `init` мод объявляет роль `economy` с умениями `balance`, `transfer`, `currencies`, `top`,
`history` и подаёт на неё две заявки: свою именем `codeeconomy` и мост к ForgeEssentials именем
`forgeessentials`. Кто держит роль, решает ядро по ключу `economy` в секции `[owners]` главного
файла: `auto` отдаёт её нашему моду, `off` не отдаёт никому, имя отдаёт названному. Числового веса в
конфиге больше нет, его выбирает ядро по тому, как назван владелец.

Роль ушла другому или стоит `off`, и CodeEconomy отходит целиком: ни `/pay`, ни `/eco`, ни журнала,
ни чекпоинта, ни одного созданного файла. Файлы прошлого запуска остаются нетронутыми, поэтому
возврат имени в `[owners]` возвращает и деньги. При старте в лог уходит строка о том, кто держит
роль и какой провайдер хранилища назван в главном файле.

Мост к ForgeEssentials закрывает `balance` и `transfer`, а `currencies`, `history` и `top` не умеет:
у чужого мода одна валюта, целый счёт и никакого журнала. Его перевод собирается из `withdraw` у
одного кошелька и `add` у другого, между ними нет ни атомарности, ни ключа идемпотентности, и при
выборе этого владельца об этом уходит строка в лог. Второй строкой мод говорит, что личный потолок
перевода из меты `codeeconomy.paylimit` при таком владельце не работает: меты у чужого мода нет, и
действуют только `minTransfer` с `maxTransfer` из главного файла.

`EconomyApi.service()` отвечает тем же, чем реестр ядра: если экономику подменил другой мод, обе
двери ведут к нему. Подменяющий обязан воспроизвести атомарность, идемпотентность и потолки точно,
проверка это общий файл тестовых векторов `codeeconomy-conformance`.

Обычная точка расширения не подмена сервиса, а SPI: хранилище `EconomyStore` (например SQL) и
правила отказа `TransferGuard`, оба регистрируются через `EconomyApi` в фазе init своего мода.
Провайдера и цепочку гвардов мод берёт по первому обращению к деньгам, поэтому мод, загруженный
после codeeconomy, успевает зарегистрироваться. Провайдер, у которого состояние живёт в двух местах,
дополнительно реализует `StoreMaintenance`: снимок по требованию, сверка и снятие карантина.

## Что делать, если мод поднялся только для чтения

Битая строка в середине журнала означает потерянные записи: файл уходит в
`world/code/economy/economy-journal.jsonl.quarantine`, в лог попадает потерянный диапазон `seq`, и в
`economy-accounts.json` ложится признак карантина. Пока он стоит, мод поднимается только для чтения при
любом числе перезапусков. Разберитесь с карантинным файлом, потом снимите признак командой
`/eco unlock`.
